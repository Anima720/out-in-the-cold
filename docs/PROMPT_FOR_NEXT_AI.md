# 给接手 AI 的提示词（直接整段复制使用）

---

你要接手一个进行中的浏览器游戏项目：GitHub 仓库 `Anima720/out-in-the-cold`，工作分支 **`v6-sandman`**。这是一部《使命召唤：现代战争 3》风格的非官方同人战役，用 three.js 写成，模型、贴图、音效全部由代码生成，`node build.mjs` 打包成单文件 `dist/index.html`。作者是 Anima720。

**开始前，按顺序完整阅读这几个文件，读完再动手：**
1. 仓库根目录的 `HANDOFF.md`：当前状态、分支、待办顺序、已知问题。
2. `docs/v7/BACKLOG.md`：用户 30 条反馈的整理，以及各模块之间的接口约定。
3. `docs/v6/COMMON.md`：工程约定、测试钩子、无头测试方法。里面的「文件归属」表格是以前多人并行时用的，现在你一个人做，可以忽略。
4. `README.md`：文件地图和检查点编号。

**你的任务，按这个顺序做：**
1. **完成第 4 条和第 14 条。**
   - 第 4 条：敌人武器多样化（步枪、冲锋枪、霰弹枪等）；部分敌人中枪后倒地、掏手枪还击，补枪或 10–15 秒后自己死亡。
   - 第 14 条：敌我双方 AI 更聪明，双方都能近战，并且有近战动作。
   - 半成品在 `wip-ai` 分支，基线 `0caec10`，用 `git diff 0caec10 origin/wip-ai` 查看。先读懂再决定是在它基础上继续还是重写。合并到 `v6-sandman` 时注意 `HANDOFF.md` 第 4 节列出的冲突点，以及它要顺带修的问题。
2. **完成第 17 条的剩余部分。** 把各文件 `LINES` 中文字幕正文里的英文人名改成中文：
   - 人名对照：Sandman = 睡魔，Truck = 卡车，Grinch = 格林奇，Price = 普莱斯，Yuri = 尤里，Nikolai = 尼科莱，克拉辛上校 = 俄军高级将领。
   - 只改中文字幕正文，说话人标签和英文台词不要动。
   - 其他中文界面文字里的英文人名一并改掉。
3. **处理 `HANDOFF.md` 第 5 节的已知问题。** 至少要修第 1 条（步行敌人路线不认识新围栏缺口）和第 4 条（标题页文案还写着配音）。其余的能修就修，修不了的写清原因。
4. **全流程回归。** 把 `HANDOFF.md` 第 3 节列出的测试脚本都跑一遍，`window.__errors` 必须为空。
5. **美术评审循环（用户要求的流程）。**
   - 每改完一版，从固定机位各截一张图。
   - 让一个只看截图、不看代码的评审，以挑剔的美术指导的角度，按严重程度列出画面问题。
   - 按意见修改，直到只剩小问题。
   - 没有独立评审可用时，你自己严格按这个角度逐张审图。

**规则：**
- 只在 `v6-sandman` 上提交；可以开自己的分支再合并回来。**未经用户同意不要合入 `main`**，不要强推覆盖别人的分支。
- 小步提交：每完成一项就构建、测试、提交、推送，提交信息写清楚改了哪一条。
- 写代码沿用现有的紧凑风格；不加新的 npm 依赖；热循环里不要每帧分配对象；跨文件的新接口用 `G.*` 钩子加 `?.` 保护。
- 所有界面文字用简体中文；配音保持关闭。
- 声称"画面没问题"之前必须真的看过截图。软件渲染很慢：逻辑测试用 480×270、`?q=low&god=1`，暂停 requestAnimationFrame 的测试脚本要把所有挂起的回调排队放出（写法见 `tools/playtest_last_stand.py`）。
- `assets/music/END_CREDITS.mp3` 是用户决定保留的，不要删。
- 遇到需要用户拍板的设计问题（比如剧情改动、删内容），先问用户，不要自己决定。

**收尾时：**
1. 更新 `HANDOFF.md`：写明做了什么、怎么验证的、还剩什么。
2. 推送到 `v6-sandman`。
3. 用中文向用户简要汇报：每条做了什么、怎么验证的（看过哪些截图）、已知问题。
